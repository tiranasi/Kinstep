# KinStep 提示词独立评估

日期：2026-10-28。独立会话：`01a182f0-cb94-7ae1-bdc2-fe5247876654`，创建时指定模型 `gpt-6.1-terra`，未继承原对话历史。评估会话只获得冻结输入包与测试任务，未提供主会话的评审结论。

## 当前实现

图片提取与问答分别使用系统提示词。请求使用 JSON 模式；后端校验结构；前端用既定组件显示字段。识别结果或语音动作需经用户确认，再由统一业务规则更新进度。

已存在的约束包括原文转录、缺失信息留空、动作白名单、角色与阶段限制，以及平实简短的回复要求。这些约束有助于规范格式与行为，不能单独证明提取事实正确。

## 方法与结果

1. `prepare-inputs.ts` 从实际应用函数捕获两类出站请求、8个合成状态和源码快照。捕获替换了本地 fetch，未访问外部模型。
2. 独立 Terra 会话自行设计并演练15个案例：10个长辈问答、5个文本化单据。原始输出保存在 `terra-cases.json`，独立报告见 `terra-report.md`。
3. 主会话执行当前 Zod 校验和 `applyAction`，复核候选结果。全部15个输出通过格式检查；一个问答动作在模拟确认时被业务规则拒绝。
4. 单据确认复核对每个候选运行8种合成状态，保存变化明细；未连接数据库，也未修改真实记录。

### 已复核的问题

| 案例或检查 | 观察 | 结论 |
|---|---|---|
| E04：明确写着“未缴费”的药费通知 | 模型候选保留了“尚未缴费”，JSON合法；在取药待缴费状态下，若用户确认该单据，实际代码把 `medPaid` 从false更新为true | 当前数据只区分费用用途，缺少独立缴费事实；固定“确认已缴费”按钮与单据内容可能矛盾。不是未点击就自动缴费 |
| C06/C07：确认检查完成或药费已付 | 候选 action 为null，与提示词和白名单一致 | 问答动作目录尚未覆盖全部主任务，仍需使用页面按钮 |
| C10：声称20:00已服药 | 合法 doseTaken 会显示确认按钮，但按12:00合成时钟执行时被领域规则拒绝 | 应在给模型的上下文中提供当前时刻，并在显示动作前预检可执行性 |
| 构造的101字回复 | 当前回复 Schema 接受，虽然提示词要求100字以内 | 提示长度要求尚未成为硬校验；这是静态构造探针，不是Terra候选实际超长 |
| 构造的不允许动作+“请点击确认”回复 | 动作被丢弃，回复文字仍保留，界面不显示确认按钮 | 需核对动作与回复是否一致；同样属于构造契约探针 |

建议优先补充缴费状态字段、统一允许动作与当前任务、在返回动作前做业务预检，再收紧回复长度及动作与文字的一致性。

## 文件

- `inputs.json`：冻结的实际提示词、合成状态、源码及哈希。
- `terra-cases.json`：独立会话的候选输出与判断，保留原样。
- `terra-report.md`：独立报告，保留原样；其中“尚未运行校验”描述该会话自身的评估范围。
- `validator-results.json`：主会话后续运行实际结构校验及状态规则的结果。
- `contract-probes.json`：单列的静态构造契约探针，不计入15个模型演练案例。
- `prepare-inputs.ts`、`verify-cases.ts`：输入捕获与结果复核脚本。
